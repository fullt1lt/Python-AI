### Задание

Вам необходимо создать консольное приложение **Personal Finance Manager** для учёта личных доходов и расходов.

На выполнение задания даётся **1 неделя**.

Каждая финансовая операция должна содержать:

- `id` - уникальный идентификатор;
- `type` - тип операции (`income` или `expense`);
- `category` - категория;
- `title` - название или описание операции;
- `amount` - сумма;
- `date` - дата операции.

Например:

```python
{
    "id": 1,
    "type": "expense",
    "category": "Food",
    "title": "Groceries",
    "amount": 850.50,
    "date": "2026-08-12"
}
```

Все операции должны храниться в файле:

```text
transactions.json
```

Обязательные функции программы:

- добавление операции;
- поиск операции;
- удаление операции;
- обновление операции;
- просмотр всех операций;
- фильтрация операций;
- сортировка операций;
- просмотр основной статистики.

---

## Как взаимодействовать с пользователем?

При запуске приложения дать пользователю выбор:

```text
1. Добавить операцию
2. Найти операцию
3. Удалить операцию
4. Обновить операцию
5. Просмотреть все операции
6. Фильтровать операции
7. Сортировать операции
8. Статистика
0. Выйти
```

Если пользователь вводит что-либо другое, сообщить:

```text
Неверный выбор. Попробуйте снова.
```

После выполнения выбранной операции программа должна снова возвращаться в главное меню.

---

### 1. Добавить операцию

По очереди предложить пользователю ввести:

- тип операции;
- категорию;
- название;
- сумму;
- дату.

Тип операции может быть только:

```text
income
expense
```

Сумма должна быть числом больше `0`.

Дата должна вводиться в формате:

```text
YYYY-MM-DD
```

Например:

```text
2026-08-12
```

Проверять введённые данные на корректность и пустые строки.

`id` пользователь вводить не должен. Программа должна создавать уникальный `id` автоматически.

Если все данные введены корректно, добавить операцию и сохранить изменения в `transactions.json`.

При успехе вывести:

```text
Операция успешно добавлена!
```

Если данные введены некорректно, предложить пользователю повторить ввод.

---

### 2. Найти операцию

Предложить пользователю выбрать поиск:

```text
1. По ID
2. По названию
```

При поиске по `id` необходимо найти конкретную операцию.

При поиске по названию поиск должен работать без учёта регистра.

Желательно поддержать поиск по части строки.

Например:

```text
coffee
Coffee
COFFEE
```

должны давать одинаковый результат.

Если найдено несколько операций, вывести их все.

Если ничего не найдено:

```text
Операция не найдена.
```

---

### 3. Удалить операцию

Предложить пользователю ввести `id` операции.

Если операция существует, удалить её и сохранить изменения в файл.

При успехе вывести:

```text
Операция удалена!
```

Если операция не найдена:

```text
Операция не найдена.
```

---

### 4. Обновить операцию

Предложить пользователю ввести `id` операции.

Если операция найдена, пользователь должен иметь возможность изменить:

- тип;
- категорию;
- название;
- сумму;
- дату.

`id` операции изменять нельзя.

Новые данные необходимо проверить на корректность.

После успешного изменения сохранить данные и вывести:

```text
Операция обновлена!
```

Если операция не найдена:

```text
Операция не найдена.
```

---

### 5. Просмотреть все операции

Вывести все сохранённые операции.

Например:

```text
ID: 1
Тип: expense
Категория: Food
Название: Groceries
Сумма: 850.50
Дата: 2026-08-12
------------------------------
```

Если операций ещё нет:

```text
Операции отсутствуют.
```

---

### 6. Фильтровать операции

Пользователь должен иметь возможность фильтровать операции:

```text
1. По типу
2. По категории
3. По дате
```

#### По типу

Вывести только операции типа:

```text
income
```

или:

```text
expense
```

#### По категории

Например:

```text
Food
```

должен вывести все операции данной категории. Фильтрация не должна зависеть от регистра.

#### По дате

Например:

```text
2026-08-12
```

должен вывести все операции за выбранную дату.

---

### 7. Сортировать операции

Реализовать сортировку:

```text
1. По сумме
2. По дате
```

Для суммы предусмотреть:

- по возрастанию;
- по убыванию.

Для даты:

- от старых операций к новым;
- от новых операций к старым.

---

### 8. Статистика

Программа должна рассчитывать:

- общую сумму доходов;
- общую сумму расходов;
- текущий баланс.

Баланс рассчитывается как:

```text
доходы - расходы
```

Пример:

```text
=== СТАТИСТИКА ===

Доходы: 45000.00
Расходы: 18750.50
Баланс: 26249.50
```

---

### 0. Выйти

Завершить работу программы и вывести:

```text
Программа завершена. До свидания!
```

## Требования к программе

Программа не должна завершаться с ошибкой при некорректном пользовательском вводе.

Необходимо проверять:

- пустые строки;
- корректность типа операции;
- корректность суммы;
- корректность даты;
- существование операции перед изменением или удалением;
- корректность выбранного пункта меню.

Данные должны сохраняться между запусками программы.

Если `transactions.json` ещё не существует или не содержит операций, программа должна корректно запуститься с пустым списком.

Приложение необходимо разделить на несколько логических модулей.

**Всю программу нельзя писать в одном `main.py`.**

Конкретную структуру проекта необходимо продумать самостоятельно.

## Git

Git необходимо использовать **с самого начала разработки проекта**. Не нужно писать весь проект, а затем делать один большой коммит. Разделяйте работу на логические этапы.

Например:

```text
Create project structure
Add JSON storage
Add transaction creation
Add transaction search
Add update and delete
Add filters and sorting
Add statistics
Add validation
Update README
```

Названия ваших коммитов могут отличаться. Главное, чтобы история Git отражала процесс разработки проекта.
